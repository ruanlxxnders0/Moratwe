# QR Code Format Fix Instructions

## Problem
The web application was generating QR codes with Python string representation of dictionaries instead of proper JSON format. This caused the mobile app QR scanner to fail with `FormatException: unexpected character` errors.

## Solution Applied
1. **Updated QR code generation** in `events/models.py` to use `json.dumps()` instead of `str()` for data encoding
2. **Aligned data structure** with mobile app expectations (removed `rsvp_id` field to match mobile format)
3. **Created management command** to regenerate existing QR codes

## Steps to Apply the Fix

### 1. Navigate to the web application directory
```bash
cd /path/to/moratwe_web
```

### 2. Test the management command (dry run)
```bash
python manage.py regenerate_qr_codes --dry-run
```

### 3. Apply the fix to existing QR codes
```bash
python manage.py regenerate_qr_codes
```

### 4. Restart the web application
```bash
# If using systemd
sudo systemctl restart moratwe_web

# If using Docker
docker-compose restart web

# If running development server
# Just restart your development server
```

## What Changed

### Before (Broken Format)
```python
qr_data = {
    'rsvp_id': str(self.id),
    'event_id': str(self.event.id),
    'user_id': str(self.user.id),
    'qr_code_data': str(self.qr_code_data)
}
qr.add_data(str(qr_data))  # Creates Python string representation
```

### After (Fixed Format)
```python
qr_data = {
    'event_id': str(self.event.id),
    'user_id': str(self.user.id),
    'qr_code_data': str(self.qr_code_data)
}
qr.add_data(json.dumps(qr_data))  # Creates proper JSON
```

## Expected Results
- QR codes generated by the web application will now be readable by the mobile app
- Existing QR codes in emails and on the website will work after regeneration
- No more `FormatException` errors in the mobile app QR scanner
